# Session 2026-06-01 — Motion-gated VIDEO-vs-STATIC typing

**Headline:** replaced the `skin_score`-based spoof *subtype* typing with a
**motion-gated eyelid-blendshape** discriminator, validated live against an
adversarial (hard-waved photo) attack. Reverted the disproven liveness-
corroboration gate. Added the `SCREEN_STATIC` capture class, a dev-server save
endpoint, and `SCREEN_*` label handling in the analysis tooling.

Build string: `2026-06-01-motion-typing` (was `-corrob-dev`).

---

## 1. The problem the user raised

A still photo shown **on a phone screen** was classified `SPOOF (video_replay)`.
The verdict (SPOOF) was correct, but the **subtype was wrong** — it's a static
image, not a video. Root cause: the threat *type* was decided purely by
`screen_replay.skin_score`:

- `skin ≥ 30` → `VIDEO_REPLAY`
- `skin < 5`  → `STATIC_IMAGE`
- `[5, 30)`   → suppress (real-face-at-distance band)

`skin_score` is really a *"is this a glowing screen?"* detector (specular glare,
screen color, edge sharpness). **A bright screen reads `skin ≈ 70` whether it
plays a video or shows a photo** — so it cannot tell video from static. The user's
insight: *video vs image is distinguished by motion only.*

## 2. Why naive motion typing fails (the adversarial finding)

Motion-based typing was tried before (PR #90) and reverted (#93) because a
hand-waved photo logs false signals. We reproduced this rigorously with clean
live captures (only the phone in frame, `identity_changes=0`):

| signal | still photo | moved photo | **still video** | **HARD-waved photo** |
|---|---|---|---|---|
| blinks | 0 | 1 | **9** | **9** (false) |
| eye-blink blendshape var (ALL frames) | 0.04 | 0.16 | **0.43** | **0.30** |
| gaze.std_x | 0.03 | **0.21** | 0.07 | 0.19 |
| raw landmark-var (median / max) | 4 | 90 / 371 | 51 / 129 | **187 / 575** |
| face-detection ratio | ~98% | ~98% | ~98% | **73%** |

Key conclusions:
- **`gaze.std_x` is a rigid-motion artifact** — the *moved photo* (0.21) scored
  higher than the *still video* (0.07). It points the wrong way. **This also
  kills the basis of the liveness-corroboration gate** (which trusted
  `gaze.std_x ≥ 0.15`), so that gate was reverted.
- **Raw landmark-variance, blink count, blink_cv, eye-blendshape variance** all
  rise under aggressive waving — a determined attacker fakes "liveness" by
  shaking a photo. Per-frame motion magnitude alone is not safe to type on.

## 3. The discriminator that survives waving

Measure **non-rigid eyelid-blendshape variance ONLY on rigid-still frames**
(`landmark_variance.overall_var < 30`). Eyes in a photo are frozen open no
matter how it's waved; only a real video's recorded face closes its eyelids.

| capture | eyeMotion (ALL frames) | **eyeMotion (rigid-still only)** | % frames usable |
|---|---|---|---|
| still photo | 0.04 | **0.026** | 56% |
| moved photo | 0.16 | **0.058** | 24% |
| HARD-waved photo | 0.30 | **— (1% usable)** | **1%** |
| still video | 0.43 | **0.405** | 28% |

Two properties make this robust:
1. **~7× separation** on still frames: static ≤ 0.06, video 0.41.
2. **The attack self-defeats** — violent waving leaves ~1% rigid-still frames,
   so the attacker cannot even *produce* a measurable signal → defaults STATIC.

## 4. What shipped (`SessionEngine.checkTextureCollapseReplay`)

Fire/suppress is **unchanged** (skin co-signal: `skin ≥ 30` or `skin < 5` fires;
`[5,30)` suppresses — the real-face-at-distance anti-false-positive primitive).
Only the **subtype typing** changed:

```
once a texture-collapse spoof is confirmed:
  collect eyelid-blendshape variance (blink_symmetry std_left+std_right)
    over frames where landmark_variance.overall_var < 30  (rigid-still)
  if >= 5 such still frames AND median >= 0.2  -> VIDEO_REPLAY
  else                                          -> STATIC_IMAGE
  (skin_score, gaze.std_x, raw landmark-var, blink-count are NOT used to type)
```

Constants (PROVISIONAL — n=1/class, validate as multi-subject data grows):
`TYPING_RIGID_STILL_MAX=30`, `TYPING_VIDEO_EYE_MOTION_MIN=0.2`,
`TYPING_MIN_STILL_FRAMES=5`, `TYPING_MOTION_WINDOW=150`.

Tests: `SessionEngine.test.ts` — video(still, real eyelid motion)→VIDEO;
screen-photo(still, frozen)→STATIC; hard-waved(jitter+rigid)→STATIC. 260 pass.

## 5. Dataset audit (current build, 37 sessions / 21k frames)

- Verdict accuracy 33/39 (85%): **4 false-accepts** (phone replay → LIVE) +
  **2 false-rejects** (real face → SPOOF via texture veto).
- Feature ranking flipped vs older docs: `gaze.std_x` AUC 0.796 is top for
  LIVE-vs-SPOOF **but is a movement artifact** (see §2); `texture.texture_score`
  collapsed to AUC 0.625 / d′ 0.235 on current low-texture distance captures.
- The 4 false-accepts have `gaze.std_x ≤ 0.066` vs lowest LIVE 0.121 — a future
  *offensive low-gaze veto* (≈0.09) could catch them, but is a separate change.

## 6. Other findings (not changed this session)

- **3 LivenessProof axes are permanently 0** — Mouth-motion, Face-motion,
  Expression-dynamics — because their feeding analyzers (`temporal`,
  `expression_dynamics`) are disabled (`enableTemporal:false`,
  `enableExpressionDynamics:false`). Hand/Voice/Audio-sync (26 pts) are opt-in.
  UI shows these as 0, which reads like a detection failure but is a config
  decision. **Follow-up:** gray them out, or re-source from live analyzers.
- **FPS ~10 is browser-bound, not device-bound.** MiniFASNet is CPU-WASM,
  `numThreads=2` of 8 cores; MediaPipe uses WebGL (`useGpu:true`); 1080p capture;
  single heavy worker. **CUDA (GTX 1650) is unreachable from the browser** — it
  only helps the Python engine. Levers: bump WASM threads, drop to 720p, pool
  heavy workers; GPU work belongs in Python.

## 8. Open follow-ups

1. **Multi-subject + threshold lock.** Typing thresholds are n=1/class. Need
   3–5 subjects, plus floor test (a barely-blinking still video) and ceiling test
   (already done: hard-waved photo).
2. **True pose-normalized non-rigid deformation.** The robust long-term signal:
   subtract the global rigid transform, measure residual feature deformation.
   Eyelid-blendshape variance is the cheap proxy that works today.
3. **Offensive low-gaze veto** for the 4 false-accept replays (§5).
4. **False-reject fix** for real distant faces (the corroboration gate was the
   wrong tool — reverted). Needs the §2 deformation signal or a trained fuser.
